# Продажи «СНАЧАЛА УЖИН» - безопасный этап 1

**Черновик, не релиз.** Цена 1 900 ₽, один платёж, бессрочное право доступа к 1001 рецепту, без подписки. Оплата НЕ активирована, текущий публичный сайт не изменён.

## Подготовлено
- `commerce/access.py`: уникальный заказ, точная сумма в копейках, постоянное хранилище заказа и бессрочного права, идемпотентная обработка подтверждённого платежа, отзыв доступа при возврате, подписанная короткая сессия.
- `commerce/catalog_gate.py`: выдача приватного файла только после проверки сессии и купленного права; запрет пути за пределы защищённого каталога.
- `commerce/test_commerce.py`: сценарии отсутствия оплаты, поддельного подтверждения, неправильной цены, повторных уведомлений, другого покупателя, сессии и обхода директории.

**Критично:** `grant_verified_payment(...verified=True)` - только доверенная внутренняя функция. Нельзя размещать этот флаг в запросе клиента или использовать без проверки провайдера. Нынешний каталог всё ещё полностью публичный, значит этот модуль пока не защищает товар на сайте.

## До подключения продаж
1. Перенести 1001 рецепт с инструкциями из `index.html`, `full-catalog/index.html` и любых общедоступных JS/JSON в **приватное** хранилище на постоянном сервере. Клиент получает нужные данные через проверенный API. Уже опубликованные версии и история публичного GitHub остаются доступными и не станут секретными после переноса: приватная будущая исходная база и отдельная публичная оболочка необходимы.
2. Выбрать backend с постоянной БД и резервными копиями (сейчас Vercel хостит статический сайт; SQLite на эфемерном serverless FS не годится). Предпочтительна PostgreSQL; нынешний SQLite служит проверяемым прототипом. Согласовать хранение персональных данных в РФ.
3. Настроить форму Prodamus: индивидуальная ссылка с `order_id`, товаром на 1900 ₽, без рекуррентной подписки. Адрес страницы, `sys` и секрет должны задаваться через защищённое окружение backend.
4. Добавить **доверенный webhook**, который принимает multipart/form-data, проверяет заголовок `Sign` официальным алгоритмом `Hmac.verify`, после чего сверяет `payment_status=success`, идентификатор заказа, ID платежа, сумму, продукт, домен и идемпотентность. НИКОГДА не выдавать доступ из `urlSuccess` или параметра в браузере.
5. Сделать вход по email через одноразовую ссылку (короткий TTL, хранение хеша токена, одноразовое использование, защита от перебора). Сессия в Secure HttpOnly SameSite cookie. Бессрочно право на товар, **не** срок сессии. Восстановление доступа по email.
6. Закрыть продажи до проверки реального тестового платежа/подписи и тестов неоплаченного доступа, повторных webhook, возврата, входа с другого устройства, мобильной версии, РФ без VPN, текстов оферты и политики персональных данных.
