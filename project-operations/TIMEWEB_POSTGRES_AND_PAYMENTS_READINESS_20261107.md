## Критичный вопрос сети, решить ДО оплаты PostgreSQL
1. **ПОДТВЕРЖДЕНО скриншотом владельца 07.11.2026:** App Platform → `snachala-uzhin-commerce-staging` (284041) → «Сеть» → **«Приватная сеть: Отключена»**. Значит данное приложение невозможно подключить к новой приватной сети без клонирования/создания нового.
2. Официальная документация Timeweb говорит: **добавить App Platform в приватную сеть после создания невозможно**. Не пытаться подключить закрытую PostgreSQL к приложению без маршрута, иначе магазин не сможет хранить пользователей.
3. **Предпочтительно:** создать **бесплатную** приватную BGP-сеть в Москве через «Сети» → «Приватные сети» → «Создать», затем клонировать/создать тестовое приложение за тот же тариф 510 ₽ с выбором этой сети *после согласования возможного короткого одновременного биллинга двух серверов*. Проверить новый HTTPS, 403/503 и исправить BASE_URL, затем **удалить прежний сервер 284041** с явным подтверждением владельца. После этого PostgreSQL создаётся в **той же приватной сети**, без публичного IPv4. До удаления старого App пользовательские данные на старой тестовой SQLite не нужны (реальных покупателей нет).
4. **Временная альтернатива:** PostgreSQL в Москве с публичным IPv4 (+200 ₽/мес) и **жёстким firewall**, соединение только с подтверждённого и статичного исходящего IP приложения, TLS и ротация пароля. Если IP приложения меняется или нельзя ограничить входящие соединения, **этот вариант не применять**.
5. Не заказывать ни один из вариантов до проверки UI/стоимости: у существующего `TIMEWEB_API_TOKEN` намеренно **нет прав на раздел «Базы данных»**, поэтому он не способен безопасно получить собственную платную конфигурацию БД в аккаунте.
