## Критичный вопрос сети, решить ДО оплаты PostgreSQL
1. В Timeweb открыть **App Platform → snachala-uzhin-commerce-staging (284041) → Сеть** и выяснить, присоединено ли приложение к **приватной VPC** в зоне Москва ru-3. API `GET /api/v1/apps/284041` подтверждает App ID/проект/план, **но не показывает надёжного атрибута приватной сети**.
2. Официальная документация Timeweb говорит: **добавить App Platform в приватную сеть после создания невозможно**. Не пытаться подключить закрытую PostgreSQL к приложению без маршрута, иначе магазин не сможет хранить пользователей.
3. **Предпочтительно:** создать приватную сеть Москвы, перенести/клонировать тестовое приложение в эту сеть *только после отдельного согласования процедуры и возможного краткого перекрытия оплаты*, проверить HTTPS и 403, заменить прежний тестовый сервер. Дальше создать PostgreSQL в **той же приватной сети**. При переходе обязательно не создать две долгоживущие App Platform.
4. **Временная альтернатива:** PostgreSQL в Москве с публичным IPv4 (+200 ₽/мес) и **жёстким firewall**, соединение только с подтверждённого и статичного исходящего IP приложения, TLS и ротация пароля. Если IP приложения меняется или нельзя ограничить входящие соединения, **этот вариант не применять**.
5. Не заказывать ни один из вариантов до проверки UI/стоимости: у существующего `TIMEWEB_API_TOKEN` намеренно **нет прав на раздел «Базы данных»**, поэтому он не способен безопасно получить собственную платную конфигурацию БД в аккаунте.

## Создание PostgreSQL после подтверждения цены и сети
- Timeweb → проект «СНАЧАЛА УЖИН» → Базы данных → PostgreSQL 16 либо 17.
- Регион **Москва** и совместимая зона сети, фиксированный бюджет **не выше согласованного**.
- Один узел без платных реплик (пока мало покупателей), один пользователь с сильным сгенерированным паролем, база `default_db` на минимальном тарифе, если нельзя создавать дополнительную.
- Не подключать публичный IP при использовании приватного соединения; включить необходимые бэкапы; проверить сценарий восстановления в отдельной проверке.
- Учётные данные **никогда не присылать в чат и не коммитить**. Перенести закрытый `COMMERCE_DATABASE_URL` напрямую в Timeweb App Platform. Не переключать на `COMMERCE_PG_SSLMODE=disable`.
- На тестовом стенде пока сохранить `ENABLE_CHECKOUT=0` и `COMMERCE_PAYMENT_QA_APPROVED=0`. Проверить соединение, рестарт, бессрочное право, смену устройства и 403 до разрешения настоящих платежей.

## Почта и покупка
- Настроить отправителя с доменом, SMTP-SSL (порт 465 сейчас в коде), SPF/DKIM/DMARC и пробный вход на популярных российских почтовых сервисах.
- Настроить Prodamus: уникальная ссылка для каждого `order_num`; реальные `PRODAMUS_SYS`, `PRODAMUS_SECRET`, официальный подписанный callback с `Sign`. Не принимать redirect за подтверждение платежа.
- Проверить настоящую оплату 1900 ₽, сумму и товар, дубли, отмены/возвраты, отзыв доступа, чеки самозанятого, оферту и обработку ПДн в РФ.
- Только после подтверждённого E2E и восстановления из бэкапа отдельно разрешить `ENABLE_CHECKOUT=1` и `COMMERCE_PAYMENT_QA_APPROVED=1`.
