# Yandex AI ART - фотопроизводство 100 рецептов аэрогриля

**Цель:** 100 уникальных WebP-фотографий, по одной на каждый рецепт раздела «Аэрогриль».  
**Провайдер:** Yandex AI ART 3.0, тот же Yandex-проект, что используется для фотобазы сайта.  
**Статус на 07.11.2026:** конвейер работает; первые 10 фотографий партии 01 созданы и технически проверены. Партия 02 содержит следующие 10 полных черновиков и ожидает включения в main. Все изображения остаются неопубликованными.

## Как работает конвейер

1. Берёт название, точный состав и индивидуальный фото-бриф из каждого файла `data/airfryer-recipes-batch-XX.json`.
2. Создаёт отдельный prompt для каждого рецепта с ограничением Yandex в 500 символов.
3. Запрашивает одну картинку за один платный вызов, без автоматических повторов.
4. Сохраняет сырой ответ до обработки, затем создаёт WebP 1200 × 900.
5. Записывает SHA-256, модель, prompt и состав в `photo-library/airfryer/records/`.
6. Оставляет результат в статусе `generated_unpublished`; `approved_for_publication=false`.
7. Не меняет HTML и не публикует изображения на сайте.

## Порядок партий

- Рецепты объединяются в партии по 10.
- Workflow просматривает манифесты по возрастанию номера и обрабатывает первую неполную партию.
- За один запуск создаётся не более 10 новых изображений.
- Если партия завершена, следующий запуск переходит к следующей партии.
- Если модель отклонила prompt или возник неопределённый платный запрос, автоматическое продвижение останавливается до ручного решения. Дублирующий платный вызов не отправляется.
- После генерации всех 100 файлов расписание продолжает только техническую проверку существующих WebP и не расходует баланс на повторную генерацию.

## Защита от повторной оплаты

- Перед каждым запросом сохраняется маркер `uncertain`.
- Если процесс оборвался и сырого ответа нет, следующий запуск не отправляет повторный запрос автоматически.
- Если сырой ответ уже сохранён, конвейер завершает обработку без второго платного вызова.
- Отказ модели архивируется в `rejected/`; автоматического повтора нет.
- Уже сохранённые WebP проверяются по SHA-256 и пропускаются.

## Расположение

- Готовые WebP: `assets/airfryer/{recipe-id}.webp`
- Метаданные: `photo-library/airfryer/records/{recipe-id}.json`
- Сырые checkpoints: `photo-library/airfryer/raw-checkpoint/`
- Неопределённые запросы: `photo-library/airfryer/uncertain/`
- Отказы модели: `photo-library/airfryer/rejected/`
- Прогресс партий: `photo-library/airfryer/progress-*.json`

Все изображения сохраняются в отдельную ветку `photo-production/airfryer-batch-01-20261107`. Несмотря на имя ветки, она является общей фотобазой для всех партий аэрогриля. После завершения 100 изображений будет отдельный PR с файлами и статусами.

## Автоматизация

Workflow `.github/workflows/yandex-ai-airfryer-batch-01.yml`:
- на pull request выполняет только бесплатный preflight и dry-run;
- по push в main после добавления нового манифеста и по расписанию раз в час обрабатывает следующую неполную партию;
- ручной запуск требует выбора `paid_generation=yes`;
- использует GitHub Secrets `YANDEX_API_KEY` и `YANDEX_FOLDER_ID`;
- не создаёт deployment и не меняет публичный сайт.

Платные запросы в расписании используют ранее настроенный Yandex-проект и ранее выданное владельцем разрешение на фотопроизводство. На pull request платный job не запускается.

## Текущий технический статус

- Партия 01: 10/10 WebP, формат и размеры 1200 × 900 проверены, SHA-256 совпадает, отказов и неопределённых запросов нет.
- Партия 02: 10 полных рецептурных черновиков; после объединения в main конвейер автоматически возьмёт их следующими.
- Фото не проверяются визуально по одной партии. Визуальную приёмку всей фотобазы выполняем после завершения всех 100 изображений, как установлено в проекте.
- Ни одно изображение не опубликовано.
