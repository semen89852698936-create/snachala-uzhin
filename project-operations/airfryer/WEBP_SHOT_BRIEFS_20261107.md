# Аэрогриль: предметные задания на шесть оригинальных WebP (07.11.2026)

**Статус:** задания для производства изображений, не готовые фотографии и не свидетельство физического испытания. Связано с draft PR #80 и протоколом `PHYSICAL_ACCEPTANCE_PROTOCOL_20261107.md`. Не публиковать кандидатов до независимой приёмки.

## Общие правила
- Одна оригинальная горизонтальная фотография на каждый ID; локальный WebP в `assets/`, без надписей, логотипов и чужих изображений.
- Показать **готовое блюдо по фактическим ингредиентам и шагам**, а не условную иллюстрацию категории. Подача на двоих, журнальная композиция, мягкий тёплый свет, спокойный кремово-бордовый визуальный язык.
- Не добавлять яйцо, желток, сливочный соус, сыр, мясо или другие ингредиенты, отсутствующие в рецепте. Декоративные элементы не должны изображать несуществующий этап приготовления.
- Для каждой фотографии фиксировать: ID рецепта, имя файла, источник/права, дату, проверяющего, замечания по соответствию, статус `MISSING / REVIEW / ACCEPTED / REJECTED`. Пока все шесть **MISSING**.
- Генерация не подтверждает, что блюдо физически приготовлено в аэрогриле. Физические испытания записываются отдельно. Не подменять их визуальной убедительностью изображения.

## Проверка перед сменой статуса
1. Сопоставить фото с текущим JSON кандидата по ID, ингредиентам, способу, количеству порций; не полагаться на название файла.
2. Проверить, что файл действительно декодируется как WebP, расположен локально в `assets/`, уникален и не заменяет утверждённые фотографии «Нашего вечера».
3. Отдельно записать визуальную приёмку и права на изображение. Если исходник или права неясны, статус `REJECTED`.
4. Даже `ACCEPTED` WebP **не снимает** требование физического протокола PASS, тестов 1001 ID и обоих HTML, desktop/mobile, CI и сверки Vercel SHA.
5. Пока нет шести принятых файлов и шести физических PASS, не менять `photo_webp: null` и `photo_status: required` в draft PR #80.
