## Постоянное производственное правило: действовать без новых команд

**Решение владельца от 2026-11-02:** самостоятельно продолжать все активные проекты, не ожидая нового сообщения после каждого шага. При каждом запуске работать последовательно до завершения доступного безопасного объёма: проверить состояние -> выбрать приоритет -> внести реальное изменение -> протестировать -> зафиксировать результат -> перейти к следующей независимой задаче, если остались время и инструменты. Отчёт служит фиксацией выполненного, а не заменой работы.

### Внутри одного сеанса
1. Не останавливать последовательную работу только потому, что завершена отдельная подзадача. Самостоятельно выбирать следующую из проверенного реестра.
2. Не требовать согласования на безопасные обратимые действия: поиск и проверку источников, создание документов, локальные тесты, подготовку файлов, запись изменений в рабочую Git-ветку, создание черновика PR, исправление ошибок в тестовом окружении.
3. Каждое утверждение «сделано» подкреплять артефактом: путь к файлу, commit SHA, ссылкой на PR, логом проверки или реально проверенным URL.
4. После каждого этапа сохранять checkpoint: что изменилось, какие проверки пройдены, что ещё не готово, следующая самостоятельная задача. При устаревании записи сначала сверяться с GitHub и Vercel.
5. Не дублировать работу одновременных автоматизаций: перед записью перепроверять свежий HEAD/PR, применять конкурентно-безопасные изменения, создавать отдельную ветку при конфликте.

### Между сеансами
Обычный чат **не исполняет работу непрерывно** после завершения ответа. Для продвижения без сообщений владельца используется отдельная запланированная автоматизация: каждый час новый **ограниченный по времени запуск**, который выполняет доступные задачи и оставляет checkpoint. Между запусками выполнение не гарантируется. Утренний и вечерний отчёты сохраняются отдельно. Если автоматизация не запущена или сервис недоступен, честно указывать это и не выдавать план за сделанное.

### Неизменные ограничения
- Не менять production, не сливать ветки, не включать оплату, не совершать покупки, не использовать платные API без отдельного разрешения и проверки.
- Не подменять снимок фактического состояния памятью. Не повторять поиск уже сохранённых 100 WebP; работать с проверенным архивом.
- Для фотографий различать: источник, физический файл, техническую проверку, визуальное совпадение, проверку лицензии, одобрение конкретного файла, отображение на production.
- При нехватке данных или инструментов записать блокер и выполнять следующую доступную безопасную задачу, а не просить указаний на каждом шаге.
