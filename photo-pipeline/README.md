# Фото-конвейер «СНАЧАЛА УЖИН»

## Состояние

- Все 1001 рецептов извлечены непосредственно из `main/index.html#recipeData` и записаны в `photo-library/recipes.json`.
- Первые 50 рецептов и найденные ранее Pexels-кандидаты перенесены в рабочую ветку для проверки. URL-кандидаты **не считаются готовыми изображениями**.
- `photo-pipeline/worker.py` планирует следующую партию или генерирует изображения через OpenAI Images API с обязательным сохранением в отдельную ветку `photo-library/generated`.
- Фотографии никогда не публикуются автоматически. Все новые изображения получают статус `generated_pending_review`.

## Как запускается

После ревью и слияния PR GitHub Actions запускает `.github/workflows/photo-pipeline.yml` раз в час (на 17-й минуте часа UTC). Периодический запуск GitHub Actions может задерживаться или пропускаться; **не гарантируется непрерывность без пауз**. Запуск через `workflow_dispatch` предусмотрен для ручной проверки. Production на Vercel из этого workflow не обновляется.

### Два обязательных защитных условия

В GitHub Settings -> Secrets and variables -> Actions:

1. Создать **Secret** `OPENAI_API_KEY` (вводить только на GitHub; никогда не пересылать ключ в переписке). У API должен быть отдельный доступ к биллингу, подписка ChatGPT не заменяет API-оплату.
2. Создать **Variable** `PHOTO_PIPELINE_ENABLED` со значением `true` **только после успешного ревью и проверки workflow**.
3. Создать **Variable** `PHOTO_COST_APPROVED` со значением `true` **только после отдельного согласования платных API-запросов и предела расходов**.
4. Необязательные variables: `PHOTO_MAX_TOTAL=50` (по умолчанию 50) и `PHOTO_MAX_PER_RUN=10` (по умолчанию 10). Первая партия намеренно ограничена 50 изображениями. Для остальных 951 изменять потолок только после проверки первых 50.

Если хотя бы один из двух флагов не равен `true`, запуск платной генерации пропускается. Отсутствие API-ключа также останавливает работу без запросов.

### Учёт и восстановление

- `photo-library/recipes.json`: неизменяемый реестр 1001 рецепта.
- `photo-library/recipes-photo-registry.csv`: первоначальный полный список заданий.
- `photo-library/generated/<recipe-id>.jpg`: физически сохранённое изображение в ветке `photo-library/generated`.
- `photo-library/records/<recipe-id>.json`: происхождение AI, контрольная сумма, размер, дата, статус ручной проверки.
- `photo-library/summary.json`: счётчик реально сохранённых файлов.
- Пакет фиксируется коммитом после каждой сессии и продолжается с первого ещё не созданного файла.
- По умолчанию после двух ошибок запись не вызывается повторно автоматически, чтобы не расходовать бюджет бесконечно.
- Редакционная проверка соответствия продуктов, размера и композиции обязательна. Техническая проверка JPEG не доказывает смысловое соответствие блюду.
- Если запуск прервётся между платным API-вызовом и фиксацией коммита, возможна повторная оплата той же фотографии; поэтому после тестовой партии нужно оценить надёжность и стоимость.

### Пробный запуск без API и расходов

```bash
python3 -m unittest discover -s photo-pipeline -p 'test_*.py' -v
python3 photo-pipeline/worker.py --manifest photo-library/recipes.json --max-per-run 10 --max-total 50
```

Команда без `--execute` **не вызывает API**, не пишет изображения и только выводит очередь.

### Редакционная приемка

Проверка первой партии должна подтвердить: одно неповторяющееся изображение на рецепт, сходство с конкретными ингредиентами и видом блюда, правдоподобность, допустимость использования, корректное кадрирование под карточку, отсутствие текста/логотипов. После проверки статус `approved` меняется редактором по отдельному процессу; скрипт сам этого не делает.

## Ограничения

1. Код подготовлен как PR и не запускается автоматически до слияния и включения флагов.
2. OpenAI Images API платный и требует самостоятельного API-ключа; тариф зависит от модели, разрешения и количества токенов. См. https://developers.openai.com/api/docs/pricing
3. В рамках подготовительного этапа создан реестр и код. Готовых новых файлов пока не создано.
4. Ограничение 50 означает максимальное число созданных файлов, а не гарантированный лимит денег: неуспешные/повторные запросы и входные токены могут влиять на расходы.
5. Сайт `snachala-uzhin-preview.vercel.app` этим процессом не меняется.
